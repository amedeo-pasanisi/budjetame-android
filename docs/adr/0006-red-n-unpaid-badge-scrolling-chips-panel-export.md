# One red "N unpaid" badge, a one-line scrolling chips strip, and Export only in the Filters panel — mirror of web ADR-0025

The web app decided (ADR-0025 in the web repo, commit 6c32fa6) that its two Backlog signals were one fact in two words: the "Overdue" mark and the amber "N unpaid" badge both fired from a non-empty Backlog, and the summary line ("X costs overdue · N unpaid occurrences") repeated the double language — it read as two different states where users perceive one, and an Unpaid Occurrence whose due date is still ahead is not Overdue at all. The Android app mirrors that decision by adoption: the per-row Overdue mark, the summary line, and the word itself are gone; the one signal is the red "{N} unpaid" badge on each row of the Recurring Costs and Recurring Incomes screens. The port carries the same web commit's Transactions chrome as well: the filtered chips never wrap — overflow hides and the strip scrolls sideways behind edge fades, with Clear all pinned beside it — and Export to Excel leaves the chips line, its one home the filter panel's footer.

The shared backend's `RecurringCostOut`/`RecurringIncomeOut` no longer send the derived `overdue` field, so the Android DTOs drop it too. The removal is safe on either side of the backend deploy: Android's JSON config ignores unknown keys, so a backend that still sends the field parses cleanly; and a defaulted field would have hidden the removal — dropping it keeps a dead derived value from reopening the two-words-one-fact trap.

The chips strip scrolls horizontally inside the pinned sticky-head chrome of ADR-0005: the placement stays an Android divergence from the web's scroll-everything layout, while the strip's one-line scroll behavior mirrors the web exactly — that mirror is why the wrapping FlowRow is gone.
