# The Android app is a client of the shared Budjetame backend

The Android app talks to the same FastAPI/PostgreSQL backend and HTTP API as the web app: it is a second frontend, not a standalone ledger. We chose this over a self-contained app (local Room/SQLite database with the domain logic reimplemented in Kotlin) because the domain rules — derived balances, the derived Budget, Recurring Occurrence math, import verification, category merging — are nontrivial and already implemented and tested server-side; duplicating them on the phone would create two divergent ledgers and invite silent behavioral drift. A local-first-with-sync design was considered and rejected for now as a separate, much larger project. The accepted costs: the app is online-only (no local cache, no offline writes; connectivity failures surface inline error states with Retry), the backend must be reachable over TLS, and sessions are a long-lived JWT (backend `BUDJETAME_JWT_EXPIRE_MINUTES`) in Keystore-encrypted storage. The domain glossary in this repo's `CONTEXT.md` is ported verbatim from the web repo's — keep the two copies in sync when either side's language changes.
