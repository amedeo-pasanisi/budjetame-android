# Screens keep loaded data and revalidate in the background after writes

The Android app mirrors the web app's keep-alive model (web ADR-0022): a screen's ViewModel — scoped to its navigation back-stack entry, so it survives UI re-creation on tab switches — holds the last loaded data, and a global data version, bumped by the API transport after every successful non-GET, triggers background re-fetches. Screens render instantly from held data and are never stale after a write elsewhere. Chosen over refetch-on-navigation (every tab switch spends requests and shows spinners for data that didn't change) and over a per-resource GET cache (in this derived-data domain every write can change nearly every read, so the invalidation mapping would be complex and error-prone; one global clock is the honest model). Failed writes never bump, and the import pipeline's computation endpoints (POSTs that write nothing) are exempt from the bump, exactly as on the web.
